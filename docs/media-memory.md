# HTTP 500 при генерации изображений

В журнале Cloudflare обнаружены два POST `/api/projects/:id/jobs/:jobId`
с outcome `exceededMemory`. Платформа прекращает выполнение Worker и возвращает
HTML вместо JSON; обычный обработчик API не может перехватить такую остановку.
Идентификаторы маршрутов в логах скрыты, поэтому точную попытку нужно сверять
с журналом фильма, а не считать любую генерацию ошибочной.

Устранена избыточная аллокация при декодировании base64: `Uint8Array.from(atob(...), ...)`
перебирает строку через промежуточный массив. Общий декодер заранее выделяет
бинарный буфер и заполняет его блоками не более 24 КиБ. Он используется для
референсов и результатов GPT Image, загрузок ZenCreator, inline-видео Google
и проб голосов ElevenLabs. Форматы, качество, количество параллельных запросов,
квитанции и учёт стоимости не изменены.

Проверка `node tests/media-memory.mjs`: границы блоков, padding, неполный padding,
ASCII-пробелы, неверные данные и три параллельных GPT Image edits в workerd;
каждый получает два референса по 2 МиБ и возвращает изображение 6 МиБ.
Все HTTP-ответы подменены локально, платных обращений нет.

Обновление кода не восстанавливает потерянный ответ синхронной генерации.
Если результат уже сохранён, он остаётся в карточке. При неизвестном исходе
без квитанции/ссылки нужно сверить результат и списание в кабинете провайдера.
Приложение не отправляет генерацию повторно автоматически. У строк журнала
есть `data-job-id`, позволяющий сопоставить конкретную попытку с HTTP-маршрутом.
