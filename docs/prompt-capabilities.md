# Компилятор промптов и возможности моделей

`lib/prompt-compiler.ts` — чистая функция подготовки и проверки запроса. Она не вызывает модели, не загружает файлы, не создаёт задания, не меняет проект и не утверждает варианты. Один и тот же результат должен использоваться для предварительного просмотра, обычной и массовой генерации.

```ts
const prepared = compilePrompt(project, item, modelId, {
  kind: 'video',
  prompt: 'Дополнительная задача только текущего плана.',
  instruction: 'Обязательная правка режиссёра, которую нельзя исключить.',
  startFrameId: selectedStartAssetId,
  endFrameId: selectedEndAssetId,
  references: selectedReferences,
  duration: shotDuration,
});
```

Результат содержит `prompt`, упорядоченные `references` с ролями и ID, `criticalText`, `capability`, бюджет символов, отчёт исключений `compression` и предупреждения. Стоимость и резерв вычисляет сервер по фактически отправляемым референсам и настройкам качества; компилятор не выдаёт оценку расхода за подтверждённое списание.

## Содержание запроса

Из утверждённого подробного сценария берётся текущий план по постоянному ID, а для старого сценария — по точному названию. Чужой сценарий, исключённый или удалённый план не подставляется. Текущий черновик сцены не заменяет опубликованный сценарий. Для подготовки до публикации вызывающая серверная логика может явно передать проверенный `plan`; это не произвольное поле клиентского запроса.

Герои выбираются по `characterIds`, затем по точному составу `cast`; описание соседнего плана не расширяет состав. Локации выбираются по ID, а для старых проектов — по названиям. Передаются неизменная внешность, одежда и предметы участвующих героев, уже произошедшие изменения, состояние начала/конца, текущая постановка и правило речи. Неизвестные/удалённые ссылки на героев и локации требуют исправления. Положения и одежда не восстанавливаются в исходное состояние после передачи предмета или смены костюма.

Для изображения `keyframe:'start'|'end'` выбирает один момент и соответствующие состояние, крупность, внимание и положение. Для видео используются действие, оба состояния, конечная композиция, направление движения, временные действия и паузы. Начальная картинка не содержит уже выполненного будущего действия. Неподвижные ключевые картинки создаются с закрытыми ртами; в видео двигает губами только названный говорящий. Закадровая речь не открывает рты видимым героям. Утверждённый голос накладывается отдельно.

Выход предыдущего и вход следующего плана — отдельные необязательные абзацы только для стыковки. Весь общий сценарий, история всех вариантов и фотографии остальных персонажей в запрос не включаются. Краткие жанр, приёмы, воздействие и визуальный стиль дополняют постановку текущей сцены.

## Сокращение

Обязательные разделы сохраняются полностью: идентичность, одежда/предметы, релевантные изменения, состояния, правило речи, постановка действия и явный `instruction`. Если они не помещаются, `PromptCompilationError` возвращает код, требуемый размер, лимит и названия разделов. Нужно исправить описания или выбрать больший бюджет. Запрос не отправляется.

Необязательные описания разбиваются по пустым строкам. Сначала сохраняются автоматическая задача текущего плана, стиль, художественное решение и актёрская подача, затем контекст стыковки. Абзац включается целиком или исключается с указанием причины; слова и предложения не обрезаются, многоточие вместо постоянных признаков не вставляется. При совпадении текста дубликат отмечается отдельно. `prompt` совпадающий с точным `storyboardPrompt`/`videoPrompt` студии считается автоматическим повтором и может быть исключён. Любой другой пользовательский текст обязателен и не может исчезнуть при сжатии. Если UI разделяет автоматический текст и правки, обязательную правку передавайте через непустой `instruction`; тогда `prompt` используется как автоматический контекст. Пустой `instruction` не снимает защиту пользовательского текста.

`providerPromptLimit` допускается только как подтверждённый `maxLength` текущего каталога API. Он может уменьшить установленный бюджет, но не увеличить его. Символы считаются через JavaScript `length`, включая заголовки разделов и разделители; это консервативный размер строки, не оценка токенов.

## Референсы

Роли: `first-frame`, `last-frame`, `character`, `location`, `style`, `reference`. Порядок соответствует ролям, затем сохраняется порядок выбора внутри роли. Вход принимает только ID сохранённых изображений, а не URL или base64. Скрытые, удалённые и относящиеся к другим планам/героям/локациям известные изображения исключаются с отчётом. Фото-прообразы текущего героя и утверждённые ракурсы текущей локации разрешены; остальные ракурсы не выбираются автоматически.

Первый кадр можно передать явно или выбрать из референсов текущего плана; только затем используется утверждённая картинка его карточки. Чужой первый кадр не заменяется автоматически. Текст идентичности остаётся обязательным, даже если провайдер принимает только первый кадр. Дополнительные изображения такой видеомодели исключаются как неподдерживаемые и остаются видны в отчёте. Конечное изображение никогда не маскируется под изображение героя.

Чистая функция не имеет доступа к хранилищу. Для неизвестного ей ID пользовательской загрузки вызывающая API-логика обязана проверить владельца проекта, MIME, размер и доступ до резерва бюджета и отправки. Метки роли не заменяют проверку владения. Известные изображения общего стиля не подставляются автоматически; явно выбранное изображение карточки стиля получает роль `style` и используется только для техники/света, без переноса чужих персонажей.

`lib/prompt-jobs.ts` связывает компилятор с новыми попытками: `compileMediaJob(project, job, input?)` возвращает новый объект Job, итоговый промпт, упорядоченные ID референсов и `compilation` (версия компилятора, бюджет, исключения, предупреждения и роли). Видео хранит первый кадр в `refs`, дополнительные образы — в `characterRefs`. `mediaVariantPrompt` формирует одинаковое задание для просмотра и создания вариантов серии. Компилятор не применяется заново к сохранённым или уже отправленным попыткам. Смета Grok Image учитывает только референсы, которые действительно включены в запрос.

Актуальная актёрская проработка берётся из выбранного профиля Item. Физическая идентичность и источник изображения при этом остаются у утверждённого портрета. Для генерации нового портрета применяется полный текущий черновик героя, включая его внешность. Среда героя дополняется текстом связанных локаций без автоматической передачи всех фотографий мест.

Реестр сохраняет `availableForDirecting`: модели с бюджетом меньше 5 000 не предлагаются для новой подробной постановки. Они не удаляются из каталога, истории и обработки существующих заданий. Явная повторная генерация старой модели возможна через `allowLegacyModel`, с её прежним лимитом и полной проверкой обязательного текста.

Все нынешние адаптеры управляют камерой текстом; это запрос к генеративной модели, а не гарантия точной траектории. Фактические длительность, звук и движение проверяются после получения файла.

## Возможности API, которые ещё требуют подключения

Отдельное поле `upstream` не включает новые функции адаптера автоматически. На 1 октября 2026 проверено:

- Grok Video 1.5 принимает `last_frame`, сочетает его с `image` и дополнительными `reference_images`; максимум дополнительных изображений — семь. Текущий `providers.ts` ещё не передаёт конечный кадр. [Официальная документация xAI](https://docs.x.ai/developers/model-capabilities/video/reference-to-video).
- MiniMax H3 принимает элементы `content[]` с `role:first_frame` и `role:last_frame`; промпт ограничен 7 000 символами. Текущий адаптер отправляет только `first_frame`. [Официальное руководство MiniMax](https://platform.minimax.io/docs/guides/video-generation).
- fal H3 Max имеет `image_url` и `end_image_url`; текущий `fal-provider.ts` передаёт только первый. [Контракт fal H3 Max](https://fal.ai/models/minimax/h3-max/image-to-video/api).
- Grok Image допускает до пяти исходных изображений. [Официальное описание редактирования xAI](https://docs.x.ai/developers/model-capabilities/images/multi-image-editing).

Чтобы включить конец видео, нужно изменить контракт задания, загрузку файлов и тело запроса адаптера, добавить офлайн-тест обоих полей и только после этого переключить `adapter.lastFrame`. До подключения компилятор оставляет полное конечное состояние текстом и сообщает об исключённом файле. Поддержку остальных функций API нельзя выводить из возможностей похожей модели или агрегатора.

Проверки: `node tests/prompt-compiler.mjs`, без платных запросов. Интеграционные проверки API должны дополнительно подтвердить единство preview/job/provider, точный порядок отправленных изображений, фактическую смету и отказ до enqueue при ошибке обязательного текста.

`keyframeInstruction` содержит обязательную системную постановку роли ключевого кадра. Она не считается пользовательской правкой и не делает произвольный `prompt` необязательным. Для промежуточного кадра `keyframe:middle` вход и выход задают только границы движения; изображается одна промежуточная поза, а не начальное состояние. Это поле совместимо с последующим этапом парной раскадровки; оно не включает его автоматически.

Ручные действие, камера, стыковка и примечания выбранной карточки сохраняются как обязательные данные, даже если повторяющийся автоматический промпт исключён из-за бюджета. Постоянные указания к утверждённому образу героя также не обрезаются. Состав берётся из утверждённого плана: выбор или снятие фотографии не добавляет и не удаляет героя. В старых проектах без отдельного состава явно указанный говорящий герой допускается; при наличии `cast` или `characterIds` несоответствие говорящего участника останавливает запуск.
