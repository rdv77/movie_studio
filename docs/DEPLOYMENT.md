# Развёртывание на своём сервере

Студия запускается на Linux VPS без аккаунта Sites, Cloudflare D1/R2 и входа через ChatGPT. Модели вызываются через их внешние API. Основной способ установки — Docker Compose, отдельный постоянный том и Caddy для HTTPS. Предусмотрен также обычный запуск Node.js.

## Требования

- Linux x86_64 или arm64 с Docker Engine и плагином Docker Compose v2. Установка Docker: [официальная инструкция](https://docs.docker.com/engine/install/).
- Практический стартовый размер VPS: 2 vCPU, 4 ГБ RAM и 30–50 ГБ SSD; это ориентир, не результат нагрузочного теста. Объём диска определяется сохранёнными изображениями и видео. Сборка может требовать больше памяти.
- Домен с A/AAAA-записью на сервер, открытые 80/TCP и 443/TCP. 443/UDP нужен для HTTP/3, но не обязателен.
- Исходящий HTTPS к API моделей и адресам их результатов. Не направляйте клиентские запросы напрямую к API с секретными ключами.
- Современный настольный браузер. Аниматик, монтаж и подготовка sync используют его память и процессор.
- **Один экземпляр приложения, один Node-процесс, один локальный диск.** Несколько реплик, общий NFS и сетевой SQLite не поддерживаются этой конфигурацией.

Архитектура самостоятельного вывода Next.js описана в [официальной документации](https://nextjs.org/docs/app/guides/self-hosting).

## 1. Получить код

```bash
git clone https://github.com/rdv77/movie_studio.git
cd movie_studio
```

Команды ниже выполняются в корне репозитория. Здесь нет пользовательских фильмов, API-ключей и готовой `.env`.

## 2. Создать настройки и пароль

Если Node.js 24 установлен на сервере:

```bash
node scripts/setup.mjs --origin=https://studio.example.com --username=director
```

Вариант без установки Node на хост:

```bash
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/app" -w /app node:24-bookworm-slim \
  node scripts/setup.mjs --origin=https://studio.example.com --username=director
```

Замените домен. Команда создаёт `.env`, случайный пароль входа, ключ подписи сессий и ключ шифрования API-ключей. Пароль показывается один раз: сохраните его в менеджере паролей. В `.env` остаётся только хеш пароля. Существующую `.env` команда не перезаписывает.

`APP_ORIGIN` должен точно совпадать с адресом в браузере: протокол, имя и порт, без пути и завершающего `/`. Удалённый сервер требует HTTPS; HTTP допускается только для localhost/127.0.0.1/IPv6 loopback. `www` и адрес без `www` — разные адреса.

## 3. Запустить с HTTPS

```bash
docker compose -f compose.yaml -f compose.https.yaml up -d --build
docker compose -f compose.yaml -f compose.https.yaml ps
docker compose -f compose.yaml -f compose.https.yaml logs --tail=100 app
```

Первый запуск скачивает зависимости и собирает приложение. При старте автоматически применяются миграции SQLite. Caddy получает сертификат после доступности DNS и портов. Откройте `https://studio.example.com` и войдите выданным паролем.

Порт приложения опубликован только на `127.0.0.1:3000` сервера. Внешний доступ идёт через Caddy. Данные хранятся в именованном томе `studio_data`, сертификаты — в отдельных томах Caddy. Обычная пересборка контейнера данные не удаляет. Не используйте `docker compose down -v` для обновления: ключ `-v` удаляет тома.

После входа откройте **«Подключения»**, добавьте ключи нужных провайдеров и проверьте доступ. Они сохраняются зашифрованными в базе. Наличие подписки ChatGPT не заменяет API-ключ и оплату API OpenAI.

## 4. Локальный запуск Docker без домена

Создайте настройки с `--origin=http://127.0.0.1:3000`, затем:

```bash
docker compose up -d --build
```

Откройте именно `http://127.0.0.1:3000`. Для удалённого браузера используйте домен и HTTPS, а не публичный HTTP-IP.

## Запуск без Docker

Требуется Node.js 24.15+ в ветке 24 LTS. Встроенный модуль SQLite избавляет от отдельного сервера БД и нативной сборки драйвера.

```bash
npm ci
npm run setup -- --origin=http://127.0.0.1:3000 --username=director
npm run build
npm start
```

Для разработки: `npm run dev`. `npm start` читает `.env`, применяет миграции и запускает производственную сборку. `npm run db:migrate` применяет миграции отдельно. Сборка не требует реальных ключей моделей или производственной базы.

На VPS процесс должен запускаться менеджером служб, например systemd, от отдельного непривилегированного пользователя. Рабочий каталог должен быть корнем приложения; `DATA_DIR` может быть абсолютным путём вне каталога исходников. Перед ним нужен HTTPS reverse proxy. Для собственного Nginx задайте `client_max_body_size 64m`, `proxy_read_timeout 300s` и `proxy_send_timeout 300s`, передавайте исходные Host/Origin и поддерживайте потоковую выдачу видео. Установка `APP_ORIGIN` остаётся обязательной.

## Параметры `.env`

| Параметр | Назначение |
| --- | --- |
| `APP_ORIGIN` | Единственный адрес приложения, проверяемый при входе и изменениях |
| `ADMIN_USERNAME` | Логин владельца; самостоятельная версия рассчитана на одного владельца |
| `ADMIN_PASSWORD_HASH` | `scrypt:32768:8:1:<salt base64url>:<digest base64url>` |
| `SESSION_SECRET` | Случайный секрет подписи сессии; смена аннулирует сессии |
| `VAULT_KEY` | 32 случайных байта в base64 для AES-GCM; нужен для чтения API-ключей |
| `DATA_DIR` | Каталог SQLite и приватных файлов; Docker задаёт `/app/data` |
| `HOSTNAME`, `PORT` | Адрес и порт Node-процесса; внутри Docker `0.0.0.0:3000` |

Не меняйте `VAULT_KEY` при обычном обновлении. При его потере API-ключи потребуется ввести заново. Не помещайте `.env`, базу или резервные копии в GitHub.

## Обновление

Дождитесь завершения активных запросов, закройте рабочие вкладки и сделайте резервную копию по инструкции ниже. Затем:

```bash
git pull --ff-only
docker compose -f compose.yaml -f compose.https.yaml up -d --build
docker compose -f compose.yaml -f compose.https.yaml logs --tail=100 app
```

Миграции ведут журнал и проверяют контрольные суммы. Применённые SQL-файлы нельзя переписывать: изменения схемы добавляйте новой миграцией. Для отката версии со сменой схемы восстанавливайте согласованную копию данных и кода.

## Резервное копирование

Копировать нужно **весь каталог данных вместе с `.env`**, а не только `studio.sqlite`. Большие проекты ссылаются на приватные JSON-снимки; SQLite может иметь WAL-файлы. Сначала завершите генерации/загрузки и закройте вкладки.

Пример для Linux и Docker, из корня репозитория:

```bash
umask 077
mkdir -p backups
stamp=$(date -u +%Y%m%dT%H%M%SZ)
docker compose stop app
docker compose run --rm --no-deps --user root \
  -v "$PWD/backups:/backup" app \
  tar -czf "/backup/data-$stamp.tar.gz" -C /app/data .
cp .env "backups/config-$stamp.env"
docker compose start app
```

Не продолжайте обновление, если архив не создан. Храните парную копию архива и настроек вне VPS, с шифрованием и ограниченным доступом. Бэкап содержит личные материалы и секреты. Проверьте восстановление на отдельной тестовой установке.

Восстановление делается в **новый пустой том** на остановленном приложении: восстановите `.env`, распакуйте архив в `/app/data` через одноразовый контейнер и выполните `chown -R node:node /app/data`. Используйте ту же версию кода, убедитесь, что каталоги и база читаются, затем запускайте миграции/обновление. Не накладывайте архив поверх работающей или непустой базы.

## Диагностика

| Симптом | Проверка |
| --- | --- |
| Не открывается домен | DNS A/AAAA, порты 80/443, логи Caddy |
| «Вход не настроен» | Полнота `.env`, формат хеша с двоеточиями, точный `APP_ORIGIN` |
| 403 при сохранении | Адрес браузера отличается от `APP_ORIGIN` либо прокси изменяет Origin |
| 429 при входе | Подождать до 5 минут: действует ограничение попыток |
| `Permission denied` у базы | Права тома для пользователя `node`, доступность диска |
| Проект не читается после переноса | Восстановлен ли весь каталог, а не только SQLite; сохранены ли снимки |
| Ошибка провайдера 401/403 | API-ключ, доступ к модели и учётная запись провайдера |
| Генерация остановилась после закрытия страницы | Открыть нужный проект; очередь обслуживает его вкладка |
| «Исход неизвестен» | Проверить кабинет провайдера; не пересоздавать платный запрос автоматически |
| Сборка MP4 медленная | Проверить память/CPU браузера; FFmpeg выполняется на устройстве режиссёра |

`GET /api/health` возвращает только состояние готовности базы, без данных проекта. Все рабочие API и медиа требуют входа.

## Проверки для разработчика

```bash
npm ci
npm run prepare:media
npm test
npm run typecheck
npm run build
npm run test:integration
```

Регрессионные тесты используют фиктивные ответы провайдеров и временные базы. Интеграционный тест сам поднимает локальный production-сервер с временными настройками; не направляйте тесты на рабочую установку. GitHub Actions также собирает Docker-образ. Реальные платные генерации в CI не выполняются.
