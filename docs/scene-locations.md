# Локации из структуры сцен

При утверждении структуры сцен сервис выделяет постоянные места из поля «Локация» и сохраняет ссылки в `scene.locationIds`. Для прежних утверждённых сцен подготовка выполняется при открытии «Образов и локаций». Это локальная обработка описаний, без запроса к провайдеру и без расходов.

Название берётся из первой строки/предложения описания места. Одинаковые нормализованные названия используют одну карточку. Разные названия не объединяются по предположению; неоднозначные совпадения требуют ручной привязки. Формулируйте начало описания как название: «Берег лесного болота. Камыш справа…». Одно место с разными названиями можно связать вручную через «Привязка локаций, свет и состояние по сценам». Явные пользовательские связи, включая пустой список, сохраняются. Правки существующих профилей не перезаписываются.

## Действия режиссёра

1. Откройте «Образы и локации»: список покажет места и использующие их сцены.
2. Выберите локацию для редактирования, уточните постоянные признаки, географию и декорации; сохраните правки. Сохранение обязательно перед переключением или запуском серии.
3. При необходимости раскройте привязку и состояние сцен: время суток, свет, погоду, расположение и разрешённые изменения. Эти поля не показываются на этапе структуры сцен. Общую локацию можно использовать в нескольких сценах с разными состояниями.
4. Выберите подключённую модель изображений, набор «Только без изображений» либо «Все локации сцен — новые варианты» и 1–4 варианта для каждого места. Проверьте промпты и смету.
5. Нажмите «Создать изображения … локаций». Все попытки добавляются одним действием в общую параллельную очередь с ограничениями проекта и провайдера. Каждая получает собственный сохранённый профиль, промпт, референсы, стоимость и происхождение.
6. Выберите и утвердите подходящие изображения в карточках локаций. Генерация сама их не утверждает. Новые варианты и прежние оплаченные файлы сохраняются.

Картинка места генерируется без героев, надписей и коллажа, с общим визуальным стилем и сохранённым описанием конкретной локации. Другие локации не добавляются автоматически в её референсы. Для одного места с несколькими состояниями создаётся базовый образ; состояние каждой сцены передаётся отдельно при её проработке. Профиль локации и изображение связаны с конкретной сценой в последующих промптах.

## Надёжность и проверка

Серия защищена revision/CAS, проверкой владельца, доступностью ключа и модели, принадлежностью файлов, сметой и лимитом бюджета. Повтор того же batch ID не создаёт запросов повторно. Карточки с незавершённым или неизвестным запросом требуют завершения/явного решения, автоматического повтора нет. Значения сметы вычисляются сервером по модели и настройкам, а не по произвольному клиентскому числу. Фактический расход сохраняется отдельно от оценки; для неизвестного тарифа сумма не объявляется нулевой.

`tests/scene-locations.mjs` проверяет выделение/объединение, ручные связи, сохранение правок, независимость проектов, промпты, отдельные задания и перенос UI. `tests/world-routes.mjs` проверяет реальные обработчики с подменённым хранилищем/провайдером: утверждения, повтор серии, revision, авторизацию и отсутствие отправки во время подготовки. SQL-миграции не требуются.
