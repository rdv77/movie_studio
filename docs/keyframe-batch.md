# Массовое создание недостающих ключевых кадров

На этапе «Раскадровка» нажмите «Создать окончания планов» либо раскройте «Ключевые кадры · массовая генерация». По умолчанию отображаются только планы без изображения выбранной роли. Это фактическое отсутствие файла, а не отсутствие утверждения: готовый, но не выбранный вариант не считается пропуском.

1. Выберите роль: конечный или промежуточный (для тройного набора).
2. Нажмите «Выбрать все недостающие» или отметьте нужные планы. Рядом показаны выбранный первый кадр, конечный/промежуточный кадр либо пустое место. «Открыть план» переводит к его карточке.
3. Если прежние запросы имеют неизвестный исход, они не скрывают план и не запрещают отметку. Проверьте журнал: при наличии сохранённой квитанции или файла сначала попробуйте получить прежний результат. «Разрешить повтор для выбранных» одним действием разрешает новую серию для неизвестных запросов изображений в выбранных планах. Генерация этой кнопкой не запускается; прежний запрос мог быть оплачен.
4. Проверьте стоимость, количество попыток и резервную модель. Нажмите «Создать ключевые кадры». Основная модель и качество берутся из выбранного первого кадра; для загруженного вручную первого кадра предусмотрен отдельный выбор модели.
5. После получения результатов выберите подходящие варианты, затем используйте массовое утверждение готовых наборов в раскадровке.

«Все планы» позволяет заказать дополнительные варианты уже существующих изображений. Счётчики пропусков и общего числа планов независимы от возможности отправить запрос прямо сейчас. План с активной генерацией остаётся видимым с объяснением блокировки.

## Гарантии API

PATCH проекта с действием `allowMissingAdditionalFrames` принимает `role` (`end`/`middle`), уникальные `itemIds` и текущую revision. Проверяются владелец, принадлежность активной раскадровке, требуемая роль, отсутствие готового файла, наличие выбранного первого кадра, активные задачи и неизвестные задачи других типов. Весь набор проверяется до изменения разрешений; сохранение использует существующий CAS.

Разрешение снимает блокировку только неизвестных обычных запросов изображений этих планов, включая старый запрос первого кадра: очередь блокируется на уровне плана. Оно сохраняет статусы, квитанции провайдеров, расходы, файлы, выбор и утверждения. Повторное разрешение идемпотентно. Возобновление старого запроса, поступивший файл или новая активная серия требуют обновить список; сервер повторно проверяет условия при запуске. Платные обращения возможны только после отдельного запуска серии.

Проверка: `node tests/keyframe-batch.mjs` — UI и API на проекте из 16 планов с шестью пропусками; провайдеры имитированы.
