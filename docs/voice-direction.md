# Постановка речи и создание новых голосов

Модуль отделяет **что произносится**, **каким голосом** и **как исполняется реплика**. Слова реплики не заменяются техническими указаниями. Поля эмоции, намерения и целевой длительности сохраняются отдельно, а компилятор передаёт модели только документированные настройки.

## Работа режиссёра

1. Введите описание нового голоса: тембр, возрастное впечатление, дикция, характер и русский язык. Добавьте одну фразу для сравнения.
2. Для ElevenLabs выберите Voice Design v3 или v2. Один запрос возвращает несколько проб. Описание должно содержать 20–1000 символов, пробная фраза — 100–1000.
3. Для MiniMax можно запросить 1–3 варианта. Каждый вариант — отдельный запрос `/v1/voice_design` и отдельная строка расходов. Пробная фраза — до 500 символов. Студия ограничивает описание 1000 символами; это ограничение интерфейса, не утверждение об ограничении API.
4. Прослушайте готовые файлы и выберите один вариант. Прослушивание и выбор не генерируют новые пробы.
5. Нажмите «Сохранить выбранный голос». ElevenLabs создаёт ресурс голоса отдельным запросом. MiniMax уже создал `voice_id` при генерации пробы; сохранение добавляет этот ID в проект без дополнительного запроса.
6. Выберите сохранённый профиль для новой озвучки. Явный общий выбор обновляет модель и Voice ID по умолчанию; назначение «Голос этого плана» сохраняется отдельно и имеет приоритет над общим профилем пакетной озвучки. Создание или сохранение профиля не выбирает его автоматически и не меняет утверждённые аудиофайлы.
7. Для реплики задайте эмоцию, актёрскую задачу, темп, паузы и ориентир длительности. Можно запросить предложение агента, сравнить предложения и явно применить понравившееся. Затем создайте новую озвучку и прослушайте её перед утверждением.

Пауза привязывается к уникальному буквальному фрагменту реплики. Если фрагмент повторяется, расширьте его до уникальной фразы. Пауза не ставится внутри слова или после последних слов. Если текст изменился после предложения агента, его автоматическое применение отклоняется: агент должен работать с актуальной репликой.

Целевая длительность **не является точным временем результата**. TTS не получает выдуманный параметр `duration`. После генерации измеряется готовая запись. Если она длиннее видеоплана, режиссёр сокращает реплику, меняет темп и повторяет озвучку либо явно увеличивает монтажную длительность. Автоматическое ускорение и обрезание речи не выполняются.

## Поддерживаемые параметры

| Провайдер | Настройки исполнения |
| --- | --- |
| MiniMax Speech | `voice_setting.emotion`, `speed`; паузы `<#0.40#>` между словами. `language_boost: Russian`. |
| ElevenLabs v3 | `voice_settings.speed/stability/similarity_boost/style`; поддерживаемые теги эмоций и `[pause]`/`[long pause]`. Тег паузы не гарантирует заданные секунды. |
| ElevenLabs Multilingual v2 / Flash / Turbo | `voice_settings`; SSML `<break time="0.40s" />`. Эмоциональные теги v3 не отправляются. |

Для совместимости студия ограничивает темп ElevenLabs диапазоном 0,7–1,2. MiniMax допускает 0,5–2 в API. `intention` хранится как режиссёрская задача и контекст агента, но не добавляется к словам TTS. Неподдерживаемые настройки показываются в предупреждениях предпросмотра.

## Запросы, стоимость и восстановление

Каждая попытка сначала сохраняется как `Job`, затем отдельный исполнитель получает её через CAS. Два потребителя не отправляют один оплачиваемый запрос дважды. В журнале остаются фактический запрос, ID ответа, ответ агента, ошибки, оценка и фактическая стоимость.

Оценка MiniMax Voice Design вычисляется на сервере по документированному тарифу пробного аудио **$30 за 1 млн символов**. Это оценка, а не подтверждённое списание. ElevenLabs Voice Design зависит от тарифа аккаунта, поэтому оценка остаётся неизвестной. Если API не сообщает денежную стоимость, `actual` остаётся `null`, а не нулём. Ограниченный бюджет не допускает попытки с неизвестной оценкой.

Сетевой обрыв после отправки обозначается как `unknown`. Автоматического повтора нет. Остановка ожидания не отменяет принятый провайдером запрос и не гарантирует отсутствие списания. Поздние пробы и квитанции сохраняются для просмотра без автоматического выбора. Если голос ElevenLabs был сохранён у провайдера после остановки, его добавляют в проект отдельным действием.

Аудиопробы сохраняются в принадлежащие проекту файлы. Base64/hex не записываются в JSON проекта. До регистрации файла байты остаются во временном приватном объекте, поэтому при сбое сохранения можно повторить **сохранение полученного файла**, не повторяя генерацию. Удаление серии или профиля обратимо; созданные файлы и расходы не уничтожаются.

## API и интеграция

`POST /api/projects/:id/voice-design` принимает `{revision, action, data}`. Действия:

- `design`: `{batchId, input:{provider,name,description,previewText,model?,variants?}}`;
- `advance`: `{jobId?}` — исполнитель одной очередной попытки либо сохранение уже полученного файла;
- `selectPreview`: `{designId,previewId}`;
- `saveVoice`: `{batchId,designId}`; `importSavedVoice`: `{jobId}` для подтверждённого позднего сохранения;
- `saveProfile`: `{profileId?,profile}`; `chooseProfile`: `{profileId}`;
- `assignProfile`: `{itemId,profileId}` — назначение профиля конкретному плану, `null` снимает назначение;
- `saveDelivery`: `{itemId,delivery}`;
- `proposeDelivery`: `{batchId,itemId,model,instruction}`; `applyDelivery`: `{candidateId}`;
- `stop`: `{jobId}`; `removeDesign/restoreDesign`: `{designId}`; `removeProfile/restoreProfile`: `{profileId}`.

Опциональные общие типы `Project.voiceStudio`, `Job.purpose = 'voice-design'`, `Job.voiceWorkflow` и постановка записи уже предусмотрены. До подключения модуля обычный исполнитель медиа должен передавать такие попытки `runVoiceWorkflowStep`, исключая их из обычного `generate`; фоновый worker использует тот же исполнитель. Для TTS single/batch/test routes нужно вызвать `freezeVoiceJob` до сохранения очереди, а провайдерам делегировать `generateDirectedSpeech`. Без постановки helper возвращает `undefined` и остаётся прежний запрос TTS. Готовый вариант сохраняет использованные настройки, исходную чистую реплику и фактическую длительность. `projectAssetIds` включает файлы проб и профилей, включая удалённую историю.

Основной UI подключает `VoiceStudioEditor` с `submit(action,data)`, моделью текстового агента и ключом проекта. В нём выбирается план для исполнения, а библиотека и пробы голоса показаны один раз. Для отдельной карточки доступен `VoiceDirectionEditor`. Старые проекты не получают новых полей при чтении; старые выборы, утверждения, голоса и аудио сохраняются. Точный план интеграции приведён в `docs/voice-direction-integration.md`.

## Проверки

`node tests/voice-direction.mjs` — чистые схемы, реальные параметры TTS, паузы, хронометраж, профили, замороженные предложения и SSR без запросов.

`node tests/voice-design.mjs` — настоящий route/provider/runner с моками HTTP, файлов и CAS: multiple previews, explicit save, тариф/бюджет, duplicate claim, unknown/no retry, поздний ответ, сохранение файла без повторной генерации. Оплачиваемых запросов тесты не выполняют.

`node tests/voice-tts.mjs` — замороженные профили и исполнение, legacy fallback, реальные документированные TTS тела запросов через мок HTTP, сохранение квитанции при некорректном ответе, transport unknown без повтора, общий UI без вызовов.
