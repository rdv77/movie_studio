# Понятные действия и выбор опорных кадров

В новом фильме доступны две независимые настройки: **способ постановки** и **опорные изображения**. По умолчанию новый проект создаётся с «Простые и ясно читаемые действия» и «Автоматический выбор». Изменить их можно в «Общий сценарий» → «Творческое задание»; затем нажмите «Сохранить творческое задание».

| Постановка | Как меняется задание специалистам |
| --- | --- |
| Простые и ясно читаемые действия | Одно заметное главное действие и, при необходимости, короткая реакция. Герой, предмет, причина и результат видны. Не связывать смысл с цепочкой мелких физических контактов. |
| Сбалансированная постановка | Совмещать действие и реакцию, если зритель успевает их прочитать. Проверять сложные взаимодействия. |
| Сложная выразительная постановка | Допускать более сложные действия и камеру; для точного результата может понадобиться больше проб. |

В «Подробном сценарии» → правки плана → «Постановка этого плана» можно оставить наследование или выбрать отдельный режим. Изменение конкретного плана требует его обычной проверки и утверждения. Правила получают сценаристы, специалисты сцен, планировщик, оператор, художник, актёрский специалист и редактор. Изменения утверждённых событий предлагаются режиссёру отдельно, а не применяются скрыто.

| Опорные изображения | Поведение новых карточек |
| --- | --- |
| Автоматический выбор | Обычно одна начальная картинка. Пара нужна, когда оператор или пользователь явно отмечает необходимость точной конечной композиции (`direction.requiresEndFrame`). Само движение камеры или различие описаний не требует второй картинки. |
| Только начальный кадр | Одна начальная картинка; конечное состояние остаётся в текстовом задании. |
| Начальный и конечный кадры | Две картинки. Передача последней картинки при генерации видео зависит от возможностей выбранной модели. |

В раскадровке можно явно переопределить комплект отдельного плана. Один исходный кадр допускает движение героя и камеры: это не «статичный план». Настройка сама не создаёт картинки или видео.

## Существующие фильмы

Поля `brief.stagingMode`, `brief.framePolicy` и `direction.stagingMode` необязательны. При открытии старого проекта новые значения не подставляются и его прежние правила не меняются. Сохранение глобальных предпочтений не снимает ранее сделанные утверждения и не переписывает готовые файлы или уже отправленные запросы.

При смене общей политики кадров существующие комплекты с изображениями и активными запросами сохраняют прежний выбор. Карточки только с текстовым описанием, без изображений и активных запросов, следуют новой политике. Для изменения существующего комплекта используйте режим в его карточке раскадровки. Другие изменения сюжета или конкретной постановки продолжают требовать пересмотра зависимых материалов.

## Защита задания модели

В промпте изображения или видео выбранного плана сохраняется обязательный компактный блок постановки. При сокращении через LLM его место заранее резервируется вместе с блоком мимики; оба блока восстанавливаются программой дословно. Остальное обязательное содержание можно компактно перефразировать, но нельзя удалить. Итоговый лимит проверяется после сборки.

Для нового настроенного режима больше нет общей команды удерживать неподвижную конечную позу до конца клипа. Допускается естественное микродвижение без новых событий; осмысленная пауза задаётся отдельно. В изображении по-прежнему показывается только запрошенный момент, а не несколько фаз действия. Это управление заданием, а не гарантия точного исполнения видеомоделью.

Автоматическое использование фактического конца предыдущего видео для следующего плана в этот выпуск не входит.

## Проверка

`npm run test:staging` проверяет необязательные схемы, наследование, инструкции специалистов, сохранение выбора пользователя, защиту промпта при сокращении, политику ключевых кадров, сохранение старых утверждений и элементы интерфейса. Тесты локальные, без платных генераций.
