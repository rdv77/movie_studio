# Скорость и восстановление медиа — 6 октября 2026

## Что изменилось

Для нового видеоплана компилятор передаёт действие этого плана, актуальные начало и конец, камеру, внешность, одежду, реквизит и правила речи. Первый кадр фиксирует текущее состояние. История передачи предметов, общая биография, соседние планы и посторонние локации не описываются как события текущего ролика. Ручные указания сохраняются. Одинаковые постоянные признаки удаляются только внутри одного героя или места.

LLM вызывается для сокращения только при превышении ограничения целевой модели. Первой используется подключённая GPT-6 Astra, затем Grok и MiniMax. После двух недавних ошибок модель подготовки пропускается на десять минут. Если все доступные модели не справились, видео не отправляется. В журнале остаются ответы, расходы и причина.

Готовый компактный промпт используется повторно только для совпадающих исходных секций, модели, лимита, референсов, камеры, речи и длительности в этом же проекте. Смена конечного кадра исключает повторное использование прежней подготовки. Сохранённый ответ LLM можно восстановить после ошибки записи без нового обращения к модели. Старые законченные ролики и их выбор не меняются.

## Очередь и журнал

В hosted-версии ожидание LLM и лёгкая проверка статуса провайдера освобождают место для других задач. Чтение большого снимка проекта, обработка бинарных референсов, загрузка и сохранение медиа остаются ограничены по памяти. Это не увеличивает установленный пользователем предел одновременных запросов к провайдерам.

Неизменившийся ответ `pending` не перезаписывает весь проект. Интерфейс получает короткое подтверждение, если его ревизия ещё актуальна; при любых изменениях получает полный снимок. Завершение другой генерации не мешает открыть и отправить независимую серию. Изменение основы плана или референсов требует заново проверить задание. Бюджет и принадлежность файлов проверяются сервером при конкурентном сохранении.

Для новых попыток журнал показывает очередь, подготовку промпта, запрос и ожидание провайдера, сохранение. Время провайдера включает его очередь и сетевой обмен; оно не является измерением работы GPU. Для старых попыток отсутствующие времена не вычисляются задним числом.

## Ошибки и безопасное восстановление

- GET-запросы статуса при временном сбое допускают до трёх попыток. Последующие проверки используют сохраняемую паузу 10–120 секунд.
- Платный POST не повторяется автоматически при неизвестном исходе. Это защищает от двойного списания; готовый `requestId` сохраняется для проверки того же запроса.
- «Восстановить сохранённый файл» ищет уже сохранённый файл этого проекта либо использует прежнюю ссылку результата. Новая генерация не запускается.
- Поздний ответ не заменяет завершённую попытку состоянием ожидания. После ручной остановки полученная квитанция сохраняется, но ожидание самостоятельно не возобновляется.
- Ограничения содержимого, неверные ключи и неподдерживаемые параметры не лечатся бесконечными повторами. Журнал сохраняет ограниченное безопасное пояснение провайдера.

Открытая вкладка по-прежнему нужна для долгих hosted-запросов. Постоянный самостоятельный Node-сервер может продолжать очередь без браузера. Обновление не обещает ускорить собственную очередь провайдера или гарантировать художественное качество ролика.

## Проверки

`media-reliability`, `generation-admission-progress`, `prompt-optimization-reuse`, `parallel-video` проверяют реальные исполнители и маршруты с подменёнными API. `hosted-media-memory` проверяет ограничение памяти на проекте больше 18 МБ. Эти тесты не отправляют платные запросы и не подтверждают художественное качество видео.
