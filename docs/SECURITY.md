# Безопасность самостоятельной установки

## Вход

Регистрации пользователей нет: установка рассчитана на одного владельца. Пароль проверяется через scrypt; подписанная HMAC-сессия действует 12 часов. Cookie имеет HttpOnly, SameSite=Strict и Secure при HTTPS. Заголовки прежнего хостинга не используются для определения личности.

Изменение логина, хеша пароля или `SESSION_SECRET` аннулирует существующие сессии. Выход удаляет cookie в текущем браузере. Ограничение входа — 10 попыток за 5 минут для экземпляра приложения и не более двух одновременных проверок пароля. Это не замена ограничению запросов на reverse proxy при открытом доступе в интернет.

Все изменяющие запросы проверяют точный `Origin` против `APP_ORIGIN`. Не отключайте проверку для обхода ошибок прокси: исправьте домен/протокол в настройках.

## Секреты и данные

- `.env` не включается в Git или Docker build context. Создавайте её на сервере с ограниченными правами.
- API-ключи провайдеров хранятся в SQLite в виде AES-GCM-шифртекста. `VAULT_KEY` нужен для расшифровки; резервная копия `.env` столь же чувствительна, как сами ключи.
- Сервер проверяет владельца проекта и файла до доступа. Приватные файлы не находятся в `public/` и не должны раздаваться напрямую Caddy/Nginx.
- SQLite и файлы сохраняются на локальный постоянный диск. Имена объектов вычисляются адаптером, а не используются как произвольные файловые пути.
- Запросы с неизвестным платным исходом не запускаются заново автоматически. Перед повтором сверяйте кабинет провайдера.

## Эксплуатация

Используйте HTTPS, непривилегированного пользователя контейнера и актуальный Docker/Node. Публикуйте наружу только HTTPS reverse proxy. `.env`, бэкапы и том приложения должны быть доступны только администратору. Не передавайте секреты через URL, исходники или issue.

Следите за свободным местом: удаление варианта в интерфейсе обратимо и не является физическим удалением всех байтов. Старые снимки и поколения файлов сохраняются; автоматический сборщик мусора не реализован. Не удаляйте случайные файлы из `private-files`: проекты могут на них ссылаться.

Резервные копии делаются при остановленном приложении. Не запускайте несколько экземпляров на одном `DATA_DIR`: блокировки multipart рассчитаны на один процесс. Для командной работы, внешней регистрации, SSO и кластерного развёртывания потребуется дальнейшее развитие архитектуры.

## Сообщение о проблеме

В публичные issue добавляйте только обезличенное описание, версию кода и шаги воспроизведения. Не прикладывайте `.env`, cookies, API-ключи, приватные фото/видео, SQLite и полные ответы провайдеров. Если обнаружена утечка ключа, сначала отзовите его у провайдера, затем замените в «Подключениях».
