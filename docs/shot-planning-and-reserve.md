# Планы сцен, параллельная команда и резервная модель

Перед «Подробным сценарием» появился отдельный этап «Планы сцен». Номера хранимых этапов и ID существующих материалов не меняются. Изображения, видео, голоса, расходы и прежние утверждения не сбрасываются при открытии новой страницы.

## Работа режиссёра

1. Утвердите структуру сцен. Настройте визуальный стиль, локации и героев.
2. Откройте «Планы сцен». Для фильма выберите плотность монтажа: **экономичный**, **обычный** или **подробный**. При желании задайте другой режим отдельной сцене.
3. Выберите текстовую модель и нажмите «Создать планы всех сцен» или выберите нужные сцены. Один вызов создаёт один вариант набора для одной сцены. Новые варианты сохраняются отдельно и не заменяют текущий набор.
4. В двух окнах сравнения выберите текущий набор и предложенный вариант. Варианты подписаны режимом, моделью и временем. Нажмите «Выбрать этот набор для сцены», когда определитесь.
5. Короткие карточки содержат действие, задачу плана, участников, крупность, длительность, начальное и конечное состояние, речь и стык. Через «Правки» редактируйте эти поля. Стрелки меняют порядок. «Исключить план» сохраняет его в списке восстановления. «Добавить план» создаёт новую карточку. Для объединения соседних планов отметьте их, откройте объединённый текст и сохраните после проверки. Разные говорящие остаются отдельными планами; длительность объединённого плана должна быть до 60 секунд.
6. Утвердите набор сцены или все готовые наборы. Сцена без планов остаётся незавершённой; остальные готовые наборы можно утвердить сразу.
7. Перейдите к «Подробному сценарию». Выберите сцены или отдельные планы и запустите проработку. Команда сохраняет монтажный набор и ID: режиссёр уточняет действия, оператор — камеру и монтаж, художник — оформление, автор реплик — речь, специалист по актёрам — видимую игру. Затем идут проверка выразительности сцены и редактор фильма.
8. Исправьте конфликты, утвердите готовые планы и подготовьте промпты. После этого переходите к раскадровке.

Режимы не задают фиксированное число планов. Экономичный сохраняет необходимую причинность и реакции, обычный обеспечивает сбалансированное покрытие, подробный добавляет полезные детали и точки зрения. Один перегруженный сложными действиями клип не считается экономией. Выбранный режим не изменяет уже принятый набор сам по себе — для альтернативы нужна новая генерация и выбор.

## Уже существующий фильм

На новой странице виден текущий набор из подробного сценария. Можно утвердить его без повторной генерации. Открытие страницы ничего не меняет. Старый процесс остаётся совместимым до первого сохранения настроек/набора нового этапа; после включения нового процесса команда проверяет утверждение выбранных наборов.

Планы с совпадающими ID и коротким описанием сохраняют подробную проработку. Изменённые планы требуют новой проработки; при перестановке отдельно пересматриваются соседние стыки. Другие сцены сохраняются. Исключения и перестановки передаются в карточки раскадровки/голосов/видео после применения подробного сценария, через существующую сверку по ID. Прежние файлы и расходы остаются в истории.

Если применена монтажная правка редактора — длительность, исключение, перестановка, объединение — обновлённый набор появляется на странице «Планы сцен» для повторного утверждения. Возврат сохранённой творческой версии восстанавливает её набор, сохраняя оплаченные запросы и альтернативные предложения.

## GPT и Grok одновременно

В «Параллельные модели и резерв» задайте дополнительную модель команды. Независимые задания по очереди распределяются между основной и дополнительной моделями, например GPT и Grok. Это не два альтернативных ответа на каждый план: модели делят работу. Сценарные зависимости остаются последовательными; проверки сцены и фильма выполняются после специалистов.

Задания подробной проработки и подготовки промптов разбиваются на группы до трёх планов. Целевые ID заданы явно. Соседние планы и границы сцен идут отдельно как контекст; ответы не должны менять их. Важные признаки героев, утверждённая основа и состояние текущей локации сохраняются в запросе. Большие описания соседних сцен не копируются целиком.

Настройка числа одновременных запросов находится в журнале, в настройках очереди. Существующий общий предел и пределы провайдеров продолжают действовать. Две вкладки/обработчика не отправят одну задачу дважды благодаря атомарному захвату. Скорость зависит от провайдеров: вторая модель позволяет распределять работу, но не гарантирует ускорение каждой задачи. На размещённом сайте держите студию открытой; в самостоятельной версии обработчик продолжает работу на сервере.

## Что делает резерв

Резерв включается выбором «Резервная модель». По умолчанию он выключен. Максимум одна дополнительная оплачиваемая попытка на задание допускается для полученного неправильного JSON/структуры, неполного ответа или HTTP 429. В исправляющий запрос передаются исходное задание, ошибка и сохранённый ответ, если он есть. Новый ответ проходит ту же строгую проверку. После второго сбоя требуется решение пользователя.

Каждая попытка — отдельная запись журнала с собственной моделью, квитанцией, токенами и расходом. Первая попытка не стирается. Неопределённые сетевые исходы, HTTP 5xx без подтверждённого исхода, ошибки ключа/баланса и отказы по содержимому не запускают автоматическую резервную генерацию. Резерв не является способом обхода ограничений провайдера.

Без платного повтора исправляются однозначные ошибки формата: null вместо отсутствующего необязательного поля постановки, русское описание направления вместо enum (описание сохраняется), планы из другой известной сцены в актёрском ответе. Неизвестные ID, дубли целевых планов, пропущенные планы и невозможный тайминг остаются ошибками. В прежней неудавшейся задаче нажмите «Исправить формат сохранённого ответа · без генерации». Обрезанный ответ так восстановить нельзя — запустите оператора заново по нужной сцене/планам, чтобы применялось разбиение на небольшие группы.

## Проверки

`node tests/shot-planning-reliability.mjs` проверяет режимы, предложения и сравнение, явный выбор и утверждение, исключение/восстановление/порядок, сохранение ID и других сцен, небольшие задания, GPT/Grok одновременно, двойной захват, один резерв с отдельными квитанциями и запрет автоматического повтора неизвестных исходов/отказов. Провайдеры подменены; платные вызовы не выполняются.

Дополнительно проходят directing-ready-scopes, directing-production, directing-specialists, director-runner и проверки очереди/истории/героев. Проверки типов и сборки выполняются для размещённой и самостоятельной версий. Художественное качество новых результатов оценивается после реальной генерации режиссёром.
