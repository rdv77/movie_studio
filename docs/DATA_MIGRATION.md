# Перенос существующих фильмов

Этот репозиторий содержит самостоятельный **код приложения**, без данных работающей студии. После первого запуска на VPS список проектов пустой. Публикация кода не переносит автоматически существующие фильмы или личные материалы.

## Между двумя самостоятельными установками

Переносите весь `DATA_DIR` и `.env` при остановленном приложении; сохраняйте версию исходников. Это переносит проекты, утверждения, расходы, файлы, ключи и настройки владельца. Метод описан в [развёртывании](DEPLOYMENT.md#резервное-копирование). Перед запуском на другом домене измените `APP_ORIGIN`, сохранив `VAULT_KEY`.

## Из исходной студии на Sites

У исходной установки и VPS разные механизмы хранения и идентификаторы владельца. Простое копирование JSON или SQL не переносит фильм целиком. Готового автоматического импортёра Sites в этой версии нет.

Для полного переноса требуется отдельно подготовленный, проверенный экспорт:

1. Завершить текущие действия, остановить новые генерации и зафиксировать версию данных. Не переводить запросы с неизвестным исходом в очередь повторно.
2. Экспортировать строки `projects`, `assets`, `credentials` и соответствующие объекты файлового хранилища, включая приватные `project-state/...json`. Незавершённые загрузки сначала завершить либо отменить.
3. Сохранить все project/item/variant/job/asset ID, версии, выбранные и утверждённые варианты, историю и расходы.
4. Декодировать большие снимки, сменить владельца на локального `owner` и сохранить их через новый адаптер. Старый ключ снимка включает хеш исходного владельца; один `UPDATE owner` недостаточен. Файлы на VPS хранятся под внутренними хешированными именами, поэтому их также нужно импортировать через адаптер, не простым копированием R2-ключей в каталог.
5. API-ключи проще повторно ввести в «Подключениях». Для их переноса нужны старый `VAULT_KEY` и исходный идентификатор владельца: AES-GCM привязывает шифртекст к паре `owner:provider`. Старый шифртекст нельзя просто присвоить новому владельцу.
6. На отдельной проверочной установке открыть все карточки, прослушать голоса, проверить изображения/видео, собрать тестовый аниматик и сверить число вариантов/утверждений/расходы. Только после этого переключать рабочую установку.

Оригинальную студию и резервный экспорт следует сохранять до проверки нового сервера. Не публикуйте экспорт, API-ключи или пароли в репозитории и issue. Документ описывает требования к переносу, а не утверждает, что данные уже перенесены.
