# Лимиты промптов и новые видеомодели

Обновлено 05.10.2026. Ограничение относится к конкретному API, а не ко всем вариантам семейства модели. Символы и токены учитываются отдельно.

| Адаптер | Лимит | Основание |
| --- | --- | --- |
| MiniMax H3 напрямую | 7000 символов | [Документация MiniMax](https://platform.minimax.io/docs/guides/video-generation) |
| H3 Max через fal.ai | 50 000 символов | [Схема endpoint](https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=minimax/h3-max/image-to-video), `prompt.maxLength` |
| Kling 3.0 Pro через fal.ai | 2500 символов | [Схема endpoint](https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=fal-ai/kling-video/v3/pro/image-to-video), `prompt.anyOf[].maxLength` |
| Grok Imagine Video 1.5, 720p и 1080p | 4096 символов | Предел 4096 из фактического HTTP 400 xAI от 05.10.2026; проверка длины полного текста до отправки |
| Veo 3.1 / Fast | 1024 токена | [Google](https://ai.google.dev/gemini-api/docs/veo) |
| GPT Image | 32 000 символов | Существующий контракт адаптера |
| MiniMax image-01 / Hailuo 2.3 | 1500 / 2000 символов | Существующие контракты API; доступны для старых проектов |
| ZenCreator | 5000 символов, либо меньший предел текущего `/tools` | Сохранённый подтверждённый предел и проверка каталога перед отправкой |
| Grok Image, Qwen Edit, Wan и другие без опубликованного точного предела | Технический предел студии 60 000 символов | Не объявляется лимитом API или гарантией приёма провайдером |

Для Veo студия сначала использует заведомую верхнюю оценку числа токенов по байтам UTF-8. Если она укладывается, дополнительного обращения нет. В остальных случаях запрашивается `countTokens` у выбранной модели. Подтверждённый результат ниже 1024 не запускает LLM. Если endpoint явно не поддерживает подсчёт (400/404/405/501), применяется консервативная граница: сокращённый текст укладывается также в 1024 байта UTF-8. Это **не точный токенизатор** и может сократить больше необходимого; режим показан в предпросмотре и сохранённых метаданных. Сбой сети или авторизации счётчика не считается разрешением на платную генерацию.

## Условная оптимизация

1. Компилятор собирает только относящиеся к плану секции и референсы, удаляя точные повторы. Он больше не обрезает текст до общего бюджета 5000.
2. Если текст помещается, отправляется без вызова текстовой модели.
3. Если превышает предел, подключённая текстовая модель сокращает формулировки. Цепочка: Grok 4.6 → MiniMax M2.7 → GPT-6 Astra; отсутствующие ключи пропускаются. На каждый вызов отведено 120 секунд, каждая модель вызывается не более одного раза. Следующая попытка запускается отдельным шагом очереди. После успешного fallback прежний сбой показывается предупреждением; при отказе всех доступных LLM остаётся явная ошибка.
4. Задание требует сохранить лица, одежду, реквизит, действия, камеру, начало/конец, время и закрытые рты у молчащих. Ответ обязан содержать каждую обязательную секцию. Проверяется структура и итоговая длина. Семантическую точность и качество генерации это не гарантирует: результат по-прежнему оценивает режиссёр.
5. Попытка «Оптимизация промпта» хранится отдельно в журнале со своим ID, ответом, usage и стоимостью API. Исходный промпт остаётся в родительской попытке; `prompt` содержит фактически отправляемую версию.
6. Платная генерация медиа запускается следующим шагом очереди, после повторной проверки актуальности основы. Некорректный JSON, пропуск обязательных секций или превышение длины переключают подготовку на следующую LLM. Неопределённое списание предыдущего текстового вызова сохраняется; запрос к этой же LLM и видеозапрос не повторяются. При потере обработчика watchdog через три минуты освобождает подготовку для резервной модели; поздний ответ не заменяет уже подготовленный промпт.

При жёстком денежном лимите проекта автоматический вызов LLM с неизвестной сметой блокируется существующей проверкой бюджета. Неизвестное списание не считается нулевым. Hosted-режим держит длительное сокращение в активном запросе браузера; короткий фоновый `waitUntil` используется для асинхронной отправки медиа после подготовки.

Исправление Grok применяется и к ещё не отправленным заданиям, созданным при прежнем техническом пределе 60 000. Их сохранённый промпт проверяется заново, без пересборки основы и референсов. Если нужна LLM, задание не запускается из короткого фонового окна. Отклонённая попытка с HTTP 400 остаётся в журнале; её платного автоматического повторения нет. Для новой попытки откройте тот же план → «Создать с ИИ» после завершения текущей серии.

Локальная блокировка памяти hosted-исполнителя имеет срок 10 минут: прерванный HTTP-запрос больше не может навсегда удержать остальные задачи в состоянии «сервер занят». Это не повторяет запросы и не меняет их статусы. Активная/неизвестная попытка по-прежнему защищена сохранённым состоянием и проверкой бюджета; позднее завершение старого обработчика не освобождает слот нового.

## Kling 3.0 Pro

В «Видеопланах» выберите **fal.ai · Kling 3.0 Pro**. Нужен существующий ключ fal.ai. Endpoint: `fal-ai/kling-video/v3/pro/image-to-video`. Отправляются `start_image_url`, опциональный `end_image_url`, строковая длительность 3–15 секунд и `generate_audio:false`. Собственная озвучка отключена для наложения утверждённых голосов. Отдельные `elements` в этой версии не передаются.

Выход — до 1080p; endpoint сам определяет разрешение, отдельного поля resolution нет. Пропорции задаёт первый кадр. Ориентировочная цена без аудио и elements — $0.112/сек, фактическое списание сверяется отдельно. [Параметры и стоимость fal.ai](https://fal.ai/learn/tools/how-to-use-kling-3-0-pro).

## Grok Imagine Video 1.5 · 1080p

Это отдельный пункт, использующий тот же ключ xAI и нативный ID `grok-imagine-video-1.5`, с `resolution:"1080p"`. Длительность 1–15 секунд. В запросе ровно один `image`: выбранный первый кадр. `last_frame` и `reference_images` не отправляются. Выбранный конечный кадр в проекте не удаляется — его можно использовать с другой моделью.

Режим 720p сохранён и продолжает принимать конечный кадр и дополнительные референсы. Ориентир для 1080p: $0.25 за секунду + $0.01 за входную картинку. [xAI: генерация](https://docs.x.ai/developers/model-capabilities/video/generation), [цены](https://docs.x.ai/developers/models/grok-imagine-video-1.5).

## Проверки

### Уточнения 06.10.2026

- Grok Video дополнительно проверяется по консервативной границе 4096 байт UTF-8: ответ API указывает 4096 без единицы измерения. Это защитная мера, а не подтверждённое документацией утверждение о байтовом лимите. Оптимизатор пишет краткий английский промпт с запасом 20%; исходные требования сохраняются в аудите.
- Для ZenCreator Wan 3 и Wan 2.6 Flash используются длительности 5 или 10 секунд. Документация перечисляет также 6 секунд, но текущие запросы проекта с этой длительностью были отклонены. Перед отправкой проверяются перечисления текущего каталога. Для старого задания с недостаточной оценкой стоимости автоматическое увеличение до более дорогих 10 секунд запрещено: нужна новая серия с новой сметой.
- Ошибки HTTP 400/403/422 сохраняют краткие `loc`/`msg` полей. Полные входные данные, ключи и подписанные адреса не выводятся. В журнале для fal с сохранённым request ID доступно «Уточнить ошибку провайдера»: это чтение прежнего результата, без повторной генерации.
- Для fal поддержаны канонический SDK-маршрут и документированный полный путь `/response`. Адрес должен точно соответствовать установленной модели и сохранённому номеру запроса; произвольный `response_url` игнорируется. При 404 проверяется документированный путь только чтением. Ошибка из статуса `COMPLETED` показывается сразу. Уточнение сохраняется отдельным полем, не заменяя исходную ошибку.
- Компактный инструмент браузера `read_generation_diagnostics` возвращает последние 40 попыток, размеры промптов и статусы без полного проекта, изображений и ключей. Миграция базы не нужна. Старые неудачные серии не перезапускаются автоматически.
- `tests/prompt-fallback.mjs` и `tests/provider-diagnostics.mjs` дополнительно проверяют резервные модели, бюджет, отмену, поздние ответы, сохранение списаний и безопасные подробности ошибок на подменённых ответах API.

`tests/media-prompt-limits.mjs`, `tests/prompt-optimization.mjs`, `tests/prompt-compiler.mjs`, `tests/prompt-api.mjs`, `tests/fal-video.mjs`, `tests/fal.mjs`, `tests/google-video.mjs`, `tests/media-queue-worker.mjs`, `tests/hosted-background-policy.mjs` проверяют контракты, единицы лимитов, условный вызов LLM, отсутствие повторных списаний, бюджет, отмену и принадлежность кадров. Внешние ответы подменены; тесты не создают платные изображения/видео и не оценивают визуальное качество моделей.
